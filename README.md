# [Claude로 가상 사이트 제작]

> [그린이슈 (Green Issue): 바쁜 30대 직장인이 출근 시간·생활 패턴만 고르면 '언제 무엇을 먹을지' 루틴을 제안받고, 그 구성 그대로 정기배송까지 신청할 수 있게 만든 자연주의 식료품 브랜드 웹사이트]

## 1. 링크

- **Live Demo**: https://dotdot1102.github.io/my-shop/
- **GitHub**: https://github.com/dotdot1102/my-shop.git
- **와이어프레임**: https://www.figma.com/design/DFiTcjlJXl6SDkLI7YuXFt/%EA%B7%B8%EB%A6%B0%EC%9D%B4%EC%8A%88?node-id=14-2&t=6JTcN0kkB4iVi2kb-1

## 2. 프로젝트 정보

- **제작 기간**: 2026.11.12 ~ 2026.11.16 (05일)
- **담당 역할**: 개인 프로젝트 (기여도 100%)
- **담당 범위**: 기획 → 바이브코딩 구현 → GitHub Pages 배포

## 3. 사용 기술

- **React, Vite**: [메뉴·상품 카드·버튼처럼 반복되는 화면을 컴포넌트로 나눠 쓰고, 수정 결과를 바로 확인하기 위해]
- **GitHub Pages**: 무료 배포
- **Figma**: 와이어프레임
- **Claude**: 디자인 및 바이브코딩 (화면 구현)

## 4. 주요 기능

- [**섭취 루틴 만들기**: 출근 시간 슬라이더와 생활 패턴 칩을 고르면 바로 아래에 '언제 무엇을' 먹을지와 일주일 정기배송 구성을 제안]
- [**정기배송 신청**: 루틴 구성 / 상품 직접 선택 탭, 수량을 바꾸면 상품 합계·배송비·합계가 함께 바뀌는 요약 상자]
- [**회원가입·로그인 흐름**: 비회원이 루틴 만들기에 들어오면 가입 페이지를 거쳐 원래 페이지로 돌아옴]

## 5. 트러블슈팅

### 이슈 1: [첫 배포 실패]

- **문제**: [main에 push했는데 배포 단계가 “Get Pages site failed” 오류로 멈춤]
- **원인**: [저장소 Settings → Pages가 아직 꺼져 있었음]
- **해결**: [Settings → Pages → Source를 GitHub Actions로 바꾼 뒤 다시 실행.]

### 이슈 2: [히어로 슬라이드가 느리게 느껴짐]

- **문제**: [새로고침하면 슬라이드가 잘 안 넘어가는 것처럼 보임]
- **원인**: [실제 간격은 2초 그대로였음. 마우스가 사진 위에 있으면 멈추게 되어 있는데, 사진 영역이 넓어서 계속 멈춰 있었음]
- **해결**: ["화살표·막대에서만 멈춤"으로 변경]

## 6. AI 활용 방식

- **맡긴 일**: [사이트의 첫 화면(유리 폴더 인트로)]
- **핵심 프롬프트**: "[React Bits Folder 컴포넌트의 통합 프롬프트를 붙여 넣고, "위의 프롬프트를 이용해서 사이트에 맨처음에 들어가서 띄운다음 클릭해야 메인홈화면이 나오게 해줘. 지금은 아직 변경하지마"라고 요청]"

## 7. 회고

- **배운 점**: [AI는 시킨 범위까지만 만든다. 기획 단계에서 입력 칸마다 필수 여부와 규칙을 정해 두고, 만든 뒤에도 "빠진 게 없는지" 따로 점검을 요청하는 과정이 필요하다. 요청하면 확인 절차 없이 우선 제작해서, "나한테 먼저 확인 후 제작, 다른건 변경하지마" 요청이 필요했다.]
- **아쉬운 점**: [화면 디자인과 흐름 위주로 기획하다 보니 입력 항목의 규칙을 처음에 정하지 않았다. 완성 후 점검해 보니 주문 동의 체크, 전화번호 형식 확인, 비밀번호 확인 칸, 필수 표시가 빠져 있어 뒤늦게 추가했다. 다음 프로젝트부터는 회원가입·주문처럼 입력이 있는 화면은 필수 항목, 형식 확인, 동의 체크를 체크리스트로 만들어 처음부터 확인해야겠다.]
